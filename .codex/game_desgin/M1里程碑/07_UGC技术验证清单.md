# 07 UGC 技术验证清单

## 1. 目标

在正式铺内容前，先验证绿洲启元 UGC 是否能支撑 M1 的关键规则。验证优先级高于地图和怪物内容量。

## 2. P0 验证项

| 验证项         | 成功标准           | 推荐方案                                        | 失败降级         |
| ----------- | -------------- | ------------------------------------------- | ------------ |
| V2 背包或临时收益表 | 玩家拾取物品后能被本局记录  | 优先验证 `GP_BackpackV2`；同时保留 `RunLootState` 方案 | 只用服务端临时收益表   |
| 怪物刷新        | 指定区域生成 1 波怪    | 使用怪物刷新器或手动刷怪蓝图                              | 手动 Spawn 测试怪 |
| 怪物死亡回调      | 死亡只触发 1 次服务端事件 | 在死亡事件中检查 Authority                          | 加死亡标记防重      |
| 通用掉落        | 怪物死亡生成测试物品     | 使用通用掉落组件或自定义掉落                              | 直接写入未结算表     |
| 拾取入表        | 玩家拾取后进入未结算列表   | 拾取事件写入 `RunLootState`                       | 用调试按钮模拟拾取    |
| 固定撤离触发器     | 进入区域后 8 秒结算    | 碰撞盒 / 模式触发器 + 服务端计时                         | 调试按钮模拟撤离     |
| 死亡结算        | 死亡后按规则损失       | 监听玩家死亡，处理 `RunLootState`                    | 调试按钮模拟死亡     |
| 保险箱保留       | 2 格物品死亡后保留     | 独立服务端保护列表                                   | 死亡后重新发放保护物品  |

## 3. P1 验证项

| 验证项 | 成功标准 | 用途 |
| --- | --- | --- |
| 全局伤害公式 | 能区分怪物和玩家目标 | 为后续 PVP/PVE 倍率预留 |
| Boss 占位刷新 | 能生成高价值目标并掉 Boss 材料 | M1 贪婪路线 |
| 结算 UI | 能展示带出、损失、保险箱保留 | 玩家理解规则 |
| 强化入口 | 能扣金币/强化石并提升武器伤害 | 多局成长 |

## 4. 最小验证顺序

1. 创建 1 个测试物品：金币或强化石。
2. 创建 1 个测试怪物。
3. 怪物死亡后生成测试掉落。
4. 玩家拾取后写入 `RunLootState.UnsettledItems`。
5. 玩家进入撤离触发器，物品转入已结算。
6. 玩家死亡，未保护物资损失。
7. 把 1 个物品放入保险箱，死亡后保留。
8. 跑 3 次撤离和 3 次死亡，确认没有重复发奖。

## 6. 验收标准

- 所有 P0 验证项有通过记录或明确降级方案。
- 未结算、死亡损失、保险箱不依赖未验证的物品实例扩展能力。
- 所有结算逻辑以服务端为准。
- 重复触发不会重复发奖。

## 7. 不做范围

- 完整背包 UI。
- 完整仓库系统。
- 多人贡献归属。
- PVP 区域规则。
- 付费保险箱和商业化接入。
