# 01 大厅与副本状态机

## 1. 目标

把局外大厅和局内副本拆成两个状态机，避免匹配准备、背包仓库、撤离结算互相污染。

- 大厅状态机只管理玩家是否正在匹配。
- 副本状态机只管理进入副本后的跑局、撤离、死亡和结算。
- 玩家资产在大厅读档并注入 V2 背包；副本只显示背包和穿戴，不显示仓库。

## 2. 大厅状态机

| 状态 | 含义 | 进入条件 | 退出条件 |
| --- | --- | --- | --- |
| `Idle` | 未匹配，可整理仓库和装备 | 进入大厅、取消匹配、匹配失败 | 点击开始匹配 |
| `Ready` | 已发起匹配请求，等待进入副本 | 点击开始匹配且请求成功 | 再次点击取消匹配、匹配成功进入副本、匹配失败 |

### 2.1 大厅事件

| 事件 | 触发方 | 处理 |
| --- | --- | --- |
| `OnLobbyEnter(PlayerKey)` | 大厅初始化 | 读取存档，向 V2 背包注入背包/仓库/穿戴物品 |
| `OnStartMatch()` | UI 按钮 | `Idle -> Ready`，调用 `UGCMultiMode.RequestMatch` |
| `OnCancelMatch()` | UI 按钮 | `Ready -> Idle`，调用 `UGCMultiMode.RequestCancelMatch()` |
| `OnMatchFailed()` | 匹配回调 | `Ready -> Idle` |
| `OnMatchSucceeded()` | 匹配回调 | 进入副本，副本状态初始化为 `InRun` |

### 2.2 大厅背包规则

| 内容 | 规则 |
| --- | --- |
| 存档来源 | 当前可先使用 mock 数据，后续替换为表配置或真实存档 |
| 存放部位枚举 | `Backpack`、`Warehouse`、`Equipped` |
| 装备槽位 | `EquipmentSlot.Core.MainSlot1`、`EquipmentSlot.Core.MainSlot2`、`EquipmentSlot.Core.Helmet`、`EquipmentSlot.Core.Armor` |
| 大厅背包 UI | 使用 V2 背包模式 3：背包 + 仓库 + 装备 |
| 副本背包 UI | 使用 V2 背包模式 1：背包 + 装备 |

## 3. 副本状态机

| 状态 | 含义 | 进入条件 | 退出条件 |
| --- | --- | --- | --- |
| `InRun` | 局内可行动 | 匹配成功并进入副本 | 进入撤离区、死亡、超时 |
| `Extracting` | 撤离倒计时中 | 进入固定撤离区域 | 倒计时完成、离开区域、死亡 |
| `Extracted` | 已撤离 | 撤离倒计时完成 | 进入结算 |
| `Settled` | 已结算 | 撤离或死亡规则处理完成 | 返回大厅或结束流程 |
| `Dead` | 死亡失败 | 玩家死亡且无救援 | 进入结算 |

## 4. 副本核心事件

| 事件 | 触发方 | 服务端处理 |
| --- | --- | --- |
| `OnRunEnter(PlayerKey)` | 副本初始化 | 初始化玩家副本状态为 `InRun` |
| `OnMonsterKilled(MonsterID, KillerKey)` | 怪物死亡回调 | 记录击杀，通知掉落系统 |
| `OnLootPicked(PlayerKey, Item)` | 拾取物 | 写入本局未结算收益 |
| `OnSafeBoxStore(PlayerKey, InstanceID)` | 保险箱交互 | 校验容量和物品类型，移动到保护列表 |
| `OnExtractAreaEnter(PlayerKey)` | 撤离触发器 | `InRun -> Extracting`，启动倒计时 |
| `OnExtractAreaExit(PlayerKey)` | 撤离触发器 | `Extracting -> InRun`，撤离倒计时重置 |
| `OnExtractComplete(PlayerKey)` | 倒计时完成 | `Extracting -> Extracted`，触发成功结算 |
| `OnPlayerDeath(PlayerKey)` | 角色死亡 | `InRun/Extracting -> Dead`，触发失败结算 |
| `OnSettleComplete(PlayerKey)` | 结算完成 | `Extracted/Dead -> Settled`，清理本局数据 |

## 5. 数据结构草案

```lua
LobbyState = {
    State = "Idle"
}

RunState = {
    [PlayerKey] = {
        State = "InRun",
        ExtractStartTime = 0,
        ExtractDuration = 8,
        Settled = false,
        KillCount = 0,
        EliteKillCount = 0,
        PickCount = 0,
    }
}
```

## 6. 防重规则

- 大厅读档同一名玩家在同一个 DS 生命周期内只注入一次，避免 Tick 重复加物品。
- 所有结算入口必须先检查 `Settled == false`。
- `Extracted` 和 `Dead` 只能进入一次。
- 掉落生成只允许在服务端怪物死亡回调中执行。
- 撤离倒计时完成后立即锁定玩家输入或移出局内，避免继续拾取。

## 7. 可调参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `RunTimeLimit` | 12 分钟 | 灰盒可压缩验证 |
| `ExtractDuration` | 8 秒 | 固定撤离点倒计时 |
| `ExtractResetOnExit` | true | 离开撤离区重置 |
| `DamageInterruptExtract` | false | 先不做受伤打断 |

## 8. 验收标准

- 玩家进入大厅后能获得 mock 存档物品。
- 大厅能看到并操作 V2 背包的背包、仓库和装备。
- 点击开始匹配后大厅状态从 `Idle` 进入 `Ready`。
- `Ready` 状态再次点击开始按钮会取消匹配并回到 `Idle`。
- 进入副本后副本状态初始化为 `InRun`。
- 副本中打开 V2 背包只显示背包和装备，不显示仓库。
- 玩家能从局内进入撤离成功或死亡失败结算。
- 同一名玩家同一局只结算一次。
- 连续 10 局不出现状态卡死。

## 9. 不做范围

- 队友救援和复活。
- 已撤离玩家观战。
- 断线重连。
- 多撤离点选择。
- 完整真实存档接入。
