# 06 结算强化任务

## 1. 目标

把一局结果讲清楚，并让玩家立刻看到“下一局会更强”的理由。

## 2. 结算界面信息

| 区块    | 展示内容            | 数据来源             |
| ----- | --------------- | ---------------- |
| 本局结果  | 撤离成功 / 死亡失败     | `RunState.State` |
| 带出物资  | 成功入库物品          | `ExtractedItems` |
| 损失物资  | 死亡损失物品          | `LostItems`      |
| 保险箱保留 | 死亡后保留物品         | `SafeBoxItems`   |
| 战斗统计  | 普通怪击杀、精英击杀、拾取次数 | `RunState`       |
| 成长入口  | 可强化武器和材料数量      | 仓库/已结算资源         |
|       |                 |                  |

## 3. 结算流程

1. 单局状态进入 `Extracted` 或 `Dead`。
2. 服务端锁定玩家本局收益表。
3. 按撤离/死亡规则生成 `ExtractedItems`、`LostItems`、`SafeBoxItems`。
4. 发放已结算物资。
5. 清理本局未结算表。
6. 打开结算界面。
7. 玩家可进入强化界面。

## 4. 基础强化规则

| 强化等级 | 消耗 | 效果 | 失败 |
| --- | --- | --- | --- |
| +1 | 金币 + 基础强化石 | 伤害 +8%-10% | 不失败 |
| +2 | 金币 + 基础强化石 | 伤害 +8%-10% | 不失败 |
| +3 | 金币 + 基础强化石 | 伤害 +8%-10% | 不失败 |
| +4 | 金币 + 高级强化石 | 伤害 +10%-12% | M1 不失败 |
| +5 | 金币 + 高级强化石 | 伤害 +10%-12% | M1 不失败 |

M1 只需要强化 1 项武器伤害属性，不做降级、碎装、洗练。

## 5. 任务事件埋点

M1 不做完整任务链，先记录 3 个核心事件。

| 事件 | 记录字段 | 用途 |
| --- | --- | --- |
| 击杀 | 普通怪击杀数、精英击杀数、Boss 占位击杀 | 结算展示，后续任务条件 |
| 拾取 | 拾取次数、最高品质、未结算价值 | 结算展示，后续任务条件 |
| 撤离 | 是否撤离、带出价值、损失价值 | 结算展示，后续任务条件 |

## 6. 程序接口需求

| 接口 | 用途 |
| --- | --- |
| `BuildSettlement(PlayerKey)` | 生成结算数据 |
| `GrantExtractedItems(PlayerKey, Items)` | 发放带出物资 |
| `RecordRunEvent(PlayerKey, EventName, Payload)` | 记录击杀/拾取/撤离事件 |
| `GetUpgradePreview(PlayerKey, WeaponID)` | 展示强化消耗和效果 |
| `ApplyUpgrade(PlayerKey, WeaponID)` | 扣资源并强化 |

## 7. 验收标准

- 撤离成功能看到带出物资。
- 死亡失败能看到损失物资和保险箱保留物资。
- 玩家能从结算进入强化，并完成至少 1 次强化。
- 强化后下一局伤害变化可被感知。
- 击杀、拾取、撤离 3 类事件能被正确记录。

## 8. 不做范围

- 完整每日/周常任务 UI。
- 任务奖励自动发放。
- 多武器强化策略。
- 词条洗练。
- 仓库排序和装备推荐。
