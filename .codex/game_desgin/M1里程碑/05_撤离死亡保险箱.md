# 05 撤离死亡保险箱

## 1. 目标

让玩家理解“带着好东西活着出去”的风险，同时用免费 2 格保险箱降低死亡挫败。

## 2. 固定撤离点规则

| 规则 | M1 设定 |
| --- | --- |
| 撤离点数量 | 1 个固定撤离点 |
| 开放时间 | 开局可用 |
| 倒计时 | 8 秒 |
| 离开区域 | 倒计时重置 |
| 受伤打断 | M1 不打断 |
| 成功结果 | 进入成功结算，未结算物资入库 |

## 3. 死亡损失规则

| 内容 | 死亡后处理 |
| --- | --- |
| 已穿戴装备 | 保留 |
| 保险箱物品 | 保留 |
| 未结算金币 | 损失 50% |
| 未结算基础材料 | 损失 50% |
| 未结算蓝色以上装备/材料 | 未保护则全部损失 |
| Boss 材料 | M1 默认不可保险，死亡损失 |

## 4. 保险箱规则

| 规则 | M1 设定 |
| --- | --- |
| 免费容量 | 2 格 |
| 放入方式 | 局内从未结算物资选择封存 |
| 封存动作 | M1 可先即时封存，P1 再做 3 秒动作 |
| 可保护 | 强化石、紫色材料、绿/蓝测试装备 |
| 不建议保护 | Boss 材料 |
| 死亡结果 | 保险箱物品进入保留列表 |
| 撤离结果 | 保险箱物品正常入库 |

## 5. 状态和事件

| 事件 | 条件 | 结果 |
| --- | --- | --- |
| `EnterExtractArea` | 玩家状态是 `InRun` | 进入 `Extracting`，开始倒计时 |
| `ExitExtractArea` | 玩家状态是 `Extracting` | 回到 `InRun`，倒计时清零 |
| `ExtractComplete` | 倒计时满 8 秒 | 进入 `Extracted`，触发成功结算 |
| `PlayerDeath` | 玩家未结算且未撤离 | 进入 `Dead`，触发失败结算 |
| `StoreSafeBox` | 保险箱未满且物品允许 | 物品从未结算列表移动到保险箱列表 |

## 6. 数据结构草案

```lua
SafeBoxState = {
    [PlayerKey] = {
        Capacity = 2,
        Items = {
            { InstanceID = 10002, ItemID = 8312001, Count = 1 }
        }
    }
}
```

## 7. UI/反馈需求

| 场景 | 反馈 |
| --- | --- |
| 进入撤离点 | 显示撤离倒计时 |
| 离开撤离点 | 倒计时消失或归零 |
| 撤离成功 | 显示“带出物资”列表 |
| 死亡失败 | 显示“损失物资”和“保险箱保留”列表 |
| 保险箱已满 | 提示容量不足 |
| 物品不可保险 | 提示该物品无法封存 |

## 8. 验收标准

- 玩家能在固定撤离点完成 8 秒撤离。
- 离开撤离区域后倒计时重置。
- 撤离成功后未结算物资全部入库。
- 死亡失败后已穿戴装备保留。
- 保险箱 2 格物品死亡后保留。
- 同一玩家同一局不会被重复结算。

## 9. 不做范围

- 随机撤离点。
- Boss 撤离点。
- 受伤打断封存。
- 付费保险箱扩容。
- 红名削弱保险箱。
