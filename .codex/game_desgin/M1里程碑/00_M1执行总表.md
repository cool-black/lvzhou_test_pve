# 00 M1 执行总表

## 1. 里程碑目标

M1 是灰盒闭环，不追求完整内容量。程序交付后必须能从固定入口进入一局，完成刷怪、掉落、保险箱、撤离/死亡、结算、强化、再进一局。

## 2. 开发顺序

| 顺序  | 模块       | 交付物                              | 依赖     |
| --- | -------- | -------------------------------- | ------ |
| 1   | UGC 技术门禁 | 怪物死亡回调、掉落拾取、撤离触发器、死亡损失、保险箱保留最小样例 | 无      |
| 2   | 单局状态机    | 准备、局内、撤离中、已撤离、死亡、结算状态            | 技术门禁   |
| 3   | 灰盒地图     | 出生点、普通区、精英区、Boss 占位区、固定撤离点       | 单局状态机  |
| 4   | 怪物战斗     | 行尸、枪兵、1 个精英怪、Boss 占位目标           | 地图     |
| 5   | 掉落背包     | 掉落表、拾取、未结算收益表、入库                 | 怪物死亡回调 |
| 6   | 撤离死亡保险箱  | 固定撤离倒计时、死亡损失、2 格保险箱              | 未结算收益表 |
| 7   | 结算强化     | 带出/损失/保险箱展示，武器基础强化               | 撤离死亡规则 |
| 8   | 任务事件埋点   | 击杀、拾取、撤离 3 个事件记录                 | 结算     |
| 9   | 10 局测试   | 数据记录和调参建议                        | 全模块    |

## 3. 技术门禁

以下门禁未通过前，不进入内容铺量：

| 门禁        | 通过标准                       | 失败降级方案                     |
| --------- | -------------------------- | -------------------------- |
| 怪物刷新和死亡回调 | 1 个刷新点能生成怪物，死亡只触发 1 次服务端回调 | 先手动生成怪物并监听死亡事件             |
| 掉落拾取      | 怪物死亡生成测试物品，拾取后进入本局未结算列表    | 不走正式背包，直接写入 `RunLootState` |
| 固定撤离结算    | 撤离点能稳定结算，重复进出不会重复发奖        | 使用服务端 `Extracted` 标记硬防重    |
| 死亡损失      | 死亡只损失本局未结算物资，已穿戴装备保留       | 不改正式背包，只清理 `RunLootState`  |
| 保险箱保留     | 2 格保护列表中的物品死亡后保留           | 使用独立服务端保护列表，结算时重新发放        |

## 5. M1 Done 标准

- 连续 10 局没有重复结算、物品丢失、撤离失效。
- 普通玩家单局有 3-5 次有效掉落反馈。
- 死亡后已穿戴装备保留，保险箱物品保留，未保护物资按规则损失。
- 强化后下一局普通区清怪时间下降 20% 以上。
- 结算界面能解释带出、损失、保险箱保留和强化收益。
