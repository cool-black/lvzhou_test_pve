# 04 撤离、PVP 与保险箱系统

## 1. 系统定位

撤离系统负责制造“带着好东西活着出去”的紧张感。保险箱负责降低死亡挫败，让玩家在风险中有选择。PVP 负责在高级区域制造争夺压力，但第一阶段不能压过 PVE 主体验。

第一阶段先验证撤离和保险箱，不急着开放完整 PVP。

## 2. 体验目标

- 玩家拿到好东西后，会自然产生“该不该撤”的念头。
- 撤离不是点一下结束，而是需要到达区域并等待倒计时。
- 死亡会损失未结算收益，但不会丢已穿戴核心装备。
- 保险箱容量有限，迫使玩家选择“保哪个”。
- PVP 后续只在高收益区域强化风险，不成为新手劝退点。

## 3. 撤离系统

### 3.1 撤离点类型

| 撤离点 | 开放规则 | 风险 | 第一阶段是否做 |
| --- | --- | --- | --- |
| 固定撤离点 | 开局可见，随时可用 | 容易被蹲守 | 必做 |
| 随机撤离点 | 中段随机开放 | 路线不确定 | P1 |
| Boss 撤离点 | Boss 死亡后 90 秒开放 | 高收益高风险 | P1 |

### 3.2 固定撤离点规则

- 玩家进入撤离区域后开始倒计时。
- 第一阶段倒计时建议 8-10 秒。
- 玩家离开区域，倒计时中断或重置。
- 玩家受到伤害是否打断：第一阶段先不打断，后续再评估。
- 撤离成功后立即进入结算。

### 3.3 多人撤离

第一阶段建议按个人结算：

- 每个玩家独立倒计时。
- 同队玩家可以一起撤，但不互相强绑定。
- 已撤离玩家从局内移除或进入观战。
- 未撤离队友仍可继续战斗。

这样能降低联机复杂度，也符合搜打撤“有人先走、有人继续贪”的选择。

## 4. 死亡损失

### 4.1 死亡规则

| 内容 | 死亡后处理 |
| --- | --- |
| 已穿戴装备 | 保留 |
| 保险箱物品 | 保留 |
| 未结算金币 | 损失部分 |
| 未结算材料 | 损失部分 |
| 未结算装备 | 掉落或损失 |
| Boss 核心物 | 高概率损失 |

第一阶段为了清晰，可先使用简单规则：

- 普通材料损失 50%。
- 蓝色以上未结算装备全部损失。
- 保险箱内物品全部保留。
- 已穿戴装备全部保留。

### 4.2 失败反馈

死亡结算界面必须展示：

- 你保留了什么。
- 你损失了什么。
- 保险箱救回了什么。
- 下一局还能带什么进去。

这比复杂数值更重要。

## 5. 保险箱系统

### 5.1 基础规则

- 免费玩家默认 2 格。
- 每格放 1 件小型高价值物品，或一组可堆叠材料。
- 放入保险箱需要封存动作。
- 封存时间建议 3 秒，后续可调到 3-5 秒。
- 封存过程中移动或受伤是否打断：第一阶段先用移动打断，受伤打断后续评估。

### 5.2 可保护物品

| 物品 | 是否可放入 | 说明 |
| --- | --- | --- |
| 强化石 | 可 | 保险箱基础价值 |
| 图纸碎片 | 可 | 高价值小物件 |
| 稀有材料 | 可 | 鼓励选择 |
| 蓝紫装备 | 可选 | 取决于格子大小实现 |
| Boss 核心 | 第一阶段不建议 | 避免最高目标无风险 |
| 完整红装 | 不做 | 第一阶段没有红装 |

### 5.3 保险箱决策

保险箱不是仓库扩容，而是风险选择：

- 只能在局内封存未结算物资。
- 容量少，不能什么都保。
- 高价值目标物不一定能放。
- 红名或高风险地图后续可限制容量。

## 6. PVP 系统预留

第一阶段可以暂不开放真实 PVP，但要保留区域规则接口。

### 6.1 分区

| 区域 | PVP 规则 | 第一阶段 |
| --- | --- | --- |
| 出生区 | 禁止 PVP | 必须禁止 |
| 普通刷怪区 | 禁止或极弱 PVP | 暂不开放 |
| 精英区 | 可预留争夺 | 暂不开放 |
| Boss 区 | 允许 PVP | P1 测试 |
| 撤离点 | 允许与否待测 | 第一阶段禁 PVP 或无玩家 PVP |

### 6.2 PVP 开放原则

- 不在新手路线开放 PVP。
- 不掉已穿戴装备。
- 损失集中在未结算物资。
- PVE 词条在 PVP 中衰减。
- 玩家必须能选择绕路或提前撤离。

## 7. 第一阶段要完成的功能

| 优先级 | 功能 | 交付标准 |
| --- | --- | --- |
| P0 | 固定撤离点 | 进入区域倒计时，完成后结算 |
| P0 | 撤离状态 | 玩家有未撤离、撤离中、已撤离状态 |
| P0 | 未结算结算 | 撤离成功后未结算物资入库 |
| P0 | 死亡失败 | 死亡后按规则损失未结算物资 |
| P0 | 保险箱容量 | 默认 2 格，能存放指定物品 |
| P0 | 保险箱保留 | 死亡后保险箱物品不损失 |
| P0 | 结算展示 | 分别展示带出、损失、保险箱保留 |
| P1 | 封存动作 | 3 秒交互，可被移动打断 |
| P1 | 随机撤离点 | 中段开放一个备用撤离点 |
| P1 | Boss 撤离点 | Boss 死亡后短时间开放 |
| P1 | PVP 区域开关 | Boss 区可切换允许玩家互伤 |

## 8. 开工顺序

1. 做固定撤离区域和倒计时。
2. 接撤离成功结算。
3. 接死亡失败结算。
4. 接保险箱数据结构和 2 格容量。
5. 接保险箱死亡保留。
6. 加封存动作和打断。
7. 加随机撤离点。
8. 最后再测试 PVP 区域。

## 9. 验收标准

- 玩家能清楚知道自己是否正在撤离。
- 撤离成功后，未结算物资能稳定入库。
- 死亡失败后，损失和保留结果符合预期。
- 保险箱能制造选择，而不是自动全保。
- 玩家看到结算后能理解为什么损失、为什么保留。

## 10. 主要风险

- 未结算物品实例状态难做：可先用本局收益表模拟，不直接依赖背包实例扩展。
- 保险箱被理解为付费免死：第一阶段只做免费 2 格，先验证体验。
- 撤离点被蹲守：第一阶段无 PVP 或少 PVP，后续用随机撤离点缓解。
- 死亡规则太复杂：先用固定比例，等玩家理解后再细化。
- 多人并发结算出错：每名玩家独立状态，服务端只处理一次结算。
